# PixNya 公开分发决定

> 记录日期：2026-08-09
> 状态：方向已确定，执行仍受正式发布闸门约束

## 决定

PixNya 在 `0.29.0` 阶段继续使用私人仓库和私人 Draft Release 完成生产签名基线测试。首个 stable 目标为 `1.0.0`；只有签名材料已离线备份、固定候选提交通过全部自动检查、三平台原地升级完成且维护者主动把当前源码仓库改为公开后，才允许公开 Release。

源码、tag、显式源码归档、安装包和匿名更新清单保持在同一 GitHub 仓库，不给客户端内置私人 GitHub Token，也不使用与源码提交无关的纯附件仓库。

## 已知边界

- PixNya 是非官方、个人维护的开源侧载客户端，与 pixiv Inc. 没有隶属、授权、认可或支持关系。
- “官方网页登录”只表示隔离 WebView 打开 Pixiv 页面；浏览和交互依赖现有客户端使用的非公开 App API。上游可以随时改变接口、OAuth 参数、访问策略或分发要求。
- OAuth 构建参数会进入最终二进制，不能作为能够由 APK、EXE 或 AppImage 保密的凭据。
- 项目不托管 Pixiv 内容，不运营公共代理、VPN、账号中转或镜像服务；用户仍需遵守所在地法律、Pixiv 条款和作品版权要求。
- 兼容连接会关闭上游 SNI 与证书验证；它默认关闭、不会自动回退，并在启用前披露中间人风险。
- GPL-3.0-only 只覆盖 PixNya 自身代码；Pixiv 名称、标志、内容以及第三方依赖分别归其权利人并遵循各自许可。

这是一项工程与发布治理决定，不是法律意见。若上游提出有效的停止分发要求、OAuth/API 条件发生重大变化，或安全验证无法继续 fail closed，维护者应暂停新的公开 Release 与更新入口，完成复核后再恢复。

## 每个公开 Release 必须说明

1. 非官方性质和支持的平台/架构；
2. 非公开 App API 可能失效，以及 OAuth 构建参数可被提取；
3. 低安全连接默认关闭且存在中间人风险；
4. 对应源码提交、GPL 正文、第三方许可证包、SPDX SBOM 和 SHA-256；
5. 已完成的基线到目标版本升级测试范围，以及仍未覆盖的限制。
