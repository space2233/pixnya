# 备选功能计划

> 状态：无排期，不属于 `1.1.0` 当前功能范围
> 日期：2026-08-11
> 说明：已完成的只读通知、评论删除与贴图、Ugoira 导出、官方屏蔽/静音和高级本地整理不再列为备选。

## 1. 收录规则

- 备选不等于承诺；重新激活前必须补充独立需求、风险、接口证据和验收标准。
- 每次最多激活一个主题，上游接口“看起来存在”不能作为产品承诺。
- 账号写操作必须确认授权、安全、账号归属、幂等性和失败恢复。
- Bug 修复只增加第三位；新增功能增加第二位；不兼容数据、接口或架构迁移才使用 `2.0.0`。

## 2. 账号与社区

### 多账号切换

- 为每个账号隔离 refresh token、安全存储键、缓存、下载、历史和界面设置。
- 切换账号必须取消旧账号的在途请求，不能让收藏、关注、屏蔽或静音写入错误账号。
- 当前没有版本承诺。

### 私信与直播

- 当前逆向资料没有足够可靠、可维护的 App API，继续不做。
- 即使未来出现接口，也必须独立评估内容安全、隐私和滥用风险。

### 明确不做的账号写功能

- 投稿与作品上传。
- 个人资料编辑。
- 通知已读写回、通知设置、推送注册及其他通知写操作；PixNya 的通知保持只读。

## 3. 本地与网络实验

### 云同步

- 默认不做。若未来启用，必须先确定端到端加密、冲突合并、密钥恢复和数据删除边界。
- 不上传 Pixiv token、Cookie、官方登录页面数据或未经用户选择的浏览历史。

### 网络与登录实验

- 用户自定义可信 DoH；远端配置不得扩大低安全域名白名单。
- 自带浏览器内核以强制并观测登录页 ECH；需先评估体积、安全更新负担和 Android 可行性。
- 正式版 refresh token 导入；默认仍只保留开发诊断用途。
- 兼容 IP 配置的可验证远端更新；签名配置只能收窄或替换地址，不能远程关闭更多证书验证。

## 4. 平台与架构扩展

- Windows ARM64、Linux ARM64。
- Android `x86_64`、universal APK 和恢复 ARMv7 Release。
- iOS 与 macOS；需独立评估 WebView、签名、分发和商店规则。
- 更多 Linux 包格式；当前应用内安装路线仍为 AppImage。
- 上述平台均无版本承诺；当前正式矩阵保持 Windows x64、Linux x64、Android ARM64/API 29+。

## 5. 暂停的活体验证

- Linux WebKitGTK 实机启动、登录窗口和自动更新活体测试。
- 标准、ECH、兼容三条路线的真实测试账号低频闭环。
- Android ARMv7 真实 32 位设备核心流程冒烟测试。
- Windows/Linux 新架构与更多安装包矩阵。

## 6. 永久边界

- 不内置公共代理、VPN 或项目方运营的流量中转。
- 不绕过 Pixiv 付费、年龄、地区或账号权限控制。
- 不自动批量抓取整个关注列表或作者全部作品。
- 不伪造站内通知、账号统计或不存在的上游数据。
- 不默认收集遥测、上传浏览历史或把登录凭据交给项目服务器。
